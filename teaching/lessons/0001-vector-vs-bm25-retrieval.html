Lesson 0001: Vector Search vs BM25

Mission link: this lesson makes your RAG skill interview-safe. You will know when vector search is enough, when it is wrong, and why hybrid retrieval is the stronger engineering answer.

The Win

By the end, you should be able to explain this without notes:

Vector search finds similar meaning.
BM25/full-text search finds exact words.
Hybrid retrieval uses both.

Your Current System

Your RAG script already proves this path:

PDF -> pages -> chunks -> SentenceTransformers embeddings -> ChromaDB -> top-k retrieval

That is semantic retrieval. It worked when you asked:

what is mental health?

Chroma returned chunks from Understanding Mental Health.pdf with source metadata. Good. That is resume-valid as vector retrieval.

Where Vector Search Fails

Vector search can miss cases where exact tokens matter more than general meaning:

  • error codes: HTTP 500, ERR_AUTH_401
  • invoice IDs or ticket IDs
  • policy phrases: 30 days of purchase
  • unsafe terminology examples: psycho, schizo, lunatic
  • API endpoint names: /v1/export

In those cases, BM25/full-text search is often stronger because it rewards exact term overlap.

Where BM25 Fails

BM25 can miss semantic matches when the user asks with different wording:

User asks: "How does someone's job affect their wellbeing?"
Document says: "Work can protect mental health but can also adversely affect it."

The exact words are different. Vector search is likely better.

The Professional Pattern

For serious RAG, the default mental model is not "vectorless vs vector." It is retrieval strategy:

1. Use vector search for semantic recall.
2. Use BM25/full-text for exact precision.
3. Merge or rerank results.
4. Send grounded chunks to the final answer step.
